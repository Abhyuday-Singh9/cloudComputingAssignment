# Knowledge Distillation Notes (Task 2 Preparation)

These notes summarize the readings from Kim & Rush (2016), the Pythia-70M model card, and the PyTorch Knowledge Distillation tutorial for the Task 2 explanation section.

---

## 1. Sequence-Level Knowledge Distillation (Kim & Rush, 2016)

- **Concept**:
  - In sequence-level knowledge distillation (Seq-KD), the student model is trained on complete target sequences generated by the teacher model.
  - Given an input sequence $x$, the teacher model generates an output sequence $\hat{y} = \arg\max_y P(y \mid x; \theta_T)$ (typically via greedy decoding or beam search).
  - The student model is trained by maximizing the log-likelihood of these teacher-generated sequences using standard cross-entropy loss:
    $$\mathcal{L}_{\text{Seq-KD}} = - \sum_{t=1}^{|\hat{y}|} \log P(\hat{y}_t \mid \hat{y}_{<t}, x; \theta_S)$$
- **Application to our task**:
  - The teacher model (`phi3.5`) takes a command prompt and outputs a JSON string representing the parsed intent and slots.
  - The student model (`pythia-70m`) is fine-tuned to predict this exact JSON string given `Command: <text>\nJSON:`.

---

## 2. Logit-Based Knowledge Distillation (Hinton et al., 2015; PyTorch KD Tutorial)

- **Concept**:
  - In logit-based (or word-level / token-level) knowledge distillation, the student is trained to match the full continuous probability distribution produced by the teacher at each prediction step.
  - Softmax probabilities are smoothed using a temperature parameter $T > 1$:
    $$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$
  - The loss function combines standard task loss (e.g., cross-entropy with hard labels) with Kullback-Leibler (KL) divergence between the softened teacher logits $p^T$ and student logits $p^S$:
    $$\mathcal{L}_{\text{Logit-KD}} = (1 - \alpha) \mathcal{L}_{\text{CE}} + \alpha T^2 \mathcal{D}_{\text{KL}}(p^T \parallel p^S)$$
- **Difference from Sequence-Level KD**:
  - Logit-based distillation transfers the "dark knowledge" (relative probabilities and semantic correlations among non-target tokens), whereas sequence-level distillation transfers only discrete strings without token distribution information.

---

## 3. Why Logit-Based Distillation is Not Possible Here

1. **Vocabulary and Tokenizer Discrepancy**:
   - The teacher model (`phi3.5-mini-instruct`) uses the TikToken/SentencePiece-based tokenizer with a vocabulary size of 32,064 tokens.
   - The student model (`EleutherAI/pythia-70m`) uses the GPT-NeoX BPE tokenizer with a vocabulary size of 50,304 tokens.
   - Because the vocabulary definitions, token IDs, and subword segmentations differ completely between teacher and student, token logits cannot be mapped 1:1 or aligned for KL divergence loss calculation.
2. **Black-Box API Constraints**:
   - The teacher is served via Ollama's HTTP text-generation endpoint.
   - Ollama returns the generated text string, not the full matrix of logit tensors or hidden state activations across vocabulary indices for every generation step.

---

## 4. Real Limitations of this Approach

1. **Compounded Teacher Errors**:
   - The student treats the teacher's outputs as absolute ground truth. Any misclassifications, slot hallucinations, or syntax errors made by `phi3.5` are directly learned and memorized by the student without ground truth correction.
2. **Severe Capacity Constraint (70M parameters)**:
   - Pythia-70M has ~70 million parameters, compared to Phi-3.5's 3.8 billion parameters (~54x smaller). Pythia-70M has limited syntactic and contextual reasoning capacity, making strict adherence to complex JSON schemas challenging.
3. **Loss of Distributional Diversity (Mode Collapse)**:
   - Using greedy decoding (`temperature=0`) collapses the output distribution to a single deterministic sequence per command, discarding valid alternative slot segmentations and uncertainty information.
4. **Constrained Training Set Size**:
   - Fine-tuning on at most 1,500 samples provides limited coverage over diverse linguistic phrasing, making out-of-distribution commands prone to slot-filling errors.
